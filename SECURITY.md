# Security policy

## Supported versions

Security fixes are applied to the current default branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting for this repository when it is enabled, or contact the maintainer privately through the repository owner's published contact channel.

Include a minimal reproducer, affected module/API, impact assessment, compiler/platform details, and any suggested mitigation. Acknowledgement and triage will be provided as soon as practical.

## Scope

Relevant reports include memory-safety defects, integer-overflow or wrap-around errors that violate a documented contract, malformed-input handling flaws, and unsafe build or release configuration. Denial-of-service reports should include realistic embedded or host execution conditions.
